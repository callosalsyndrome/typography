**Контекст**

Система Typography состоит из:

- **Фронтенд:** Vue.js + Vuetify (SPA)
- **Бэкенд:** Django REST Framework
- **Внешние системы:** Email-сервис, платёжная система

Необходимо выбрать протокол обмена данными между фронтендом и бэкендом, а также для интеграции с внешними системами.

**Рассмотренные альтернативы**

| Критерий     | REST          | GraphQL       | gRPC     | WebSocket     |
| ------------ | ------------- | ------------- | -------- | ------------- |
| Стиль        | Архитектурный | Язык запросов | RPC      | Дуплексный    |
| Формат       | JSON          | JSON          | Protobuf | JSON/бинарный |
| Простота     | Высокая       | Средняя       | Низкая   | Средняя       |
| Кэширование  | HTTP-кэш      | Сложное       | Нет      | Нет           |
| Опыт команды | Нет           | Нет           | Нет      | Нет           |
| Инструменты  | Postman       | GraphiQL      | grpcurl  | -             |

**Решение**

Выбран **REST** (Representational State Transfer) на базе **Django REST Framework**.

**Обоснование:**

1. **Нативная поддержка.** Django REST Framework изначально ориентирован на REST, что упрощает разработку.
2. **Опыт команды.** Postman уже выбран как клиент для тестирования API - он работает с REST.
3. **Простота.** REST использует стандартные HTTP-методы (GET, POST, PUT, DELETE) и статус-коды, что делает API понятным.
4. **Кэширование.** HTTP-кэширование снижает нагрузку на сервер.
5. **Интеграция с внешними системами.** Email-сервисы и платёжные системы предоставляют REST API.
6. **Документирование.** OpenAPI/Swagger легко генерируется из DRF.

**Исключения:**

- **WebSocket** - для чата между заказчиком и типографией (требуется двусторонняя связь в реальном времени). Реализуется через Django Channels.
- **GraphQL** - не выбран из-за отсутствия опыта у команды и усложнения кэширования.

**Последствия**

**Положительные:**

- Простой и понятный API
- Нативная поддержка в DRF
- Лёгкое тестирование через Postman
- HTTP-кэширование
- Автогенерация документации (OpenAPI)
- Стандартные инструменты мониторинга

**Отрицательные:**

- Избыточность данных (over-fetching) - клиент получает больше, чем нужно
- Недостаточность данных (under-fetching) - требуется несколько запросов для составных данных
- Для чата всё равно нужен WebSocket

**Меры митигации:**

- Использование вложенных сериализаторов DRF для составных данных
- Пагинация и фильтрация для снижения объёма передаваемых данных
- Выделение WebSocket-канала только для чата
