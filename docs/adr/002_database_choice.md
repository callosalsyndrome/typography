**Контекст**

Система Typography должна хранить:

- Учётные записи пользователей (заказчики, работники типографии)
- Заказы с параметрами (размер, материал, тираж, статус)
- Метаданные файлов (цветовое пространство, битность, PPI, размеры)
- Справочники типографий, материалов, ICC-профилей
- Историю статусов заказов (трекер-система)
- Сообщения чата
- Платежи
- Уведомления

Требуется выбрать СУБД, которая обеспечит:

- Надёжность и целостность данных
- Поддержку сложных запросов (фильтрация типографий по многим критериям)
- Масштабируемость до 10 000 пользователей и 1 000 типографий
- Объём хранилища до 10 ТБ (файлы хранятся отдельно, в БД - метаданные)

**Рассмотренные альтернативы**

| Критерий             | PostgreSQL          | MySQL          | SQLite       | MongoDB        |
| -------------------- | ------------------- | -------------- | ------------ | -------------- |
| Тип                  | Реляционная         | Реляционная    | Реляционная  | Документная    |
| Поддержка JSON       | Отличная (JSONB)    | Хорошая        | Ограниченная | Нативная       |
| Полнотекстовый поиск | Встроенный          | Встроенный     | Ограниченный | Встроенный     |
| Масштабирование      | Горизонтальное      | Горизонтальное | Нет          | Горизонтальное |
| Опыт команды         | Есть у всей команды | Нет            | Нет          | Нет            |
| Бесплатность         | Да                  | Да             | Да           | Да             |

**Решение**

Выбрана **PostgreSQL**.

**Обоснование:**

1. **Опыт команды.** Все участники имеют опыт работы с PostgreSQL (указано в обосновании выбора технологий).
2. **Реляционная модель.** Предметная область хорошо ложится на реляционную модель: пользователи, заказы, типографии, материалы - чёткие сущности со связями.
3. **JSONB для гибких данных.** Метаданные файлов (EXIF/XMP/ICC) могут храниться в JSONB-полях, что упрощает расширение без миграций.
4. **Полнотекстовый поиск.** Встроенные возможности для поиска по названиям типографий и материалов.
5. **Геоданные.** PostgreSQL с расширением PostGIS (при необходимости) позволит эффективно фильтровать типографии по расположению.
6. **Бесплатность и открытость.** Соответствует требованиям проекта.

**Последствия**

**Положительные:**

- Гибкость JSONB для метаданных файлов
- Встроенный полнотекстовый поиск
- Возможность геопространственных запросов (PostGIS)
- Хорошая интеграция с Django ORM
- Бесплатность и открытость

**Отрицательные:**

- Требуется администрирование (настройка, резервное копирование, мониторинг)
- Горизонтальное масштабирование сложнее, чем в NoSQL (но до 10 000 пользователей не критично)

**Меры митигации:**

- Использование Docker для стандартизации окружения
- Настройка ежедневного резервного копирования (NFR-7.1)
- Мониторинг производительности (NFR-7.2)
- Размещение в ЦОД на территории РФ
